# 개별종목 보유 ETF 분석기

국내 상장 ETF 전체의 구성종목(PDF)을 매일 수집해, **개별 상장주식이 ETF들에 의해
얼마나 보유되고 있는지**와 **각 ETF의 전략 변화(증량·감량·편출입)**를 웹에서 조회합니다.

- 웹 뷰어: GitHub Pages
- 데이터 출처: **KRX 정보데이터시스템** (data.krx.co.kr)
- 수집 범위: **2025 ~ 2026년 전 거래일** (계약수·ETF-in-ETF 전 기간 반영)

---

## 자동 수집 (설정 완료 — 손댈 것 없음)

**GitHub Actions가 평일 저녁 7시(KST)에 자동 실행**됩니다.
`.github/workflows/daily.yml` · 크론 `0 10 * * 1-5` (UTC 10:00 = KST 19:00)

- 내 PC가 **꺼져 있어도** GitHub 서버에서 실행됩니다.
- 크롤링 → `data/` 갱신 → 자동 커밋/푸시 → 사이트 반영까지 한 번에.
- 휴장일이나 이미 받은 날짜는 조용히 건너뜁니다(빈 커밋 없음).
- 수동 실행: GitHub → **Actions** 탭 → 워크플로 선택 → **Run workflow**.

### KRX 로그인 (GitHub Secrets)
2025-12-27 KRX 개편 이후 데이터 조회에 로그인이 필요합니다.
저장소 **Settings → Secrets and variables → Actions** 에 등록되어 있어야 합니다.

| Secret 이름 | 값 |
|---|---|
| `KRX_ID` | KRX 아이디 |
| `KRX_PW` | KRX 비밀번호 |

로컬에서 직접 돌릴 때는 같은 폴더의 `krx_계정.txt`(1줄=아이디, 2줄=비밀번호)를 사용합니다.
이 파일은 `.gitignore`로 제외되어 GitHub에 올라가지 않습니다.

## 파일 구성

| 파일/폴더 | 역할 |
|---|---|
| `etf_holdings.py` | 크롤러·집계 (Actions가 실행) |
| `index.html` | 웹 뷰어 (탭 4개 + 엑셀 다운로드) |
| `.github/workflows/daily.yml` | 자동 실행 설정 |
| `data/` | 날짜별 데이터 (아래 참조) |
| `로컬미리보기.bat` | 로컬에서 사이트 확인 (`python -m http.server`) |
| `krx_계정.txt` | 로컬 전용 계정 파일 (git 제외) |

### data 폴더 구조
- `data.json` — 날짜 목록 + 갱신 시각 (가벼움, 항상 로드)
- `stocks_<날짜>.json` — 그 날짜 종목별 집계 (비중·보유액·종가·상장주식수·보유ETF수)
- `detail_<날짜>.json` — 그 날짜 ETF별 상세 (압축형: `e`/`w`/`v`/`q`, `_etf` 메타, `_withetf` 마커)
- `etf_codes.json` — 상장 ETF 전체 코드 (시장전체 탭에서 ETF 제외용)

날짜별로 분리되어 있어, 사이트는 **선택한 날짜만** 불러옵니다(데이터가 쌓여도 느려지지 않음).

## 웹 뷰어 탭

1. **시장 전체** — 전 종목의 ETF보유비중·보유액 순위. 종목명 클릭 → 개별종목 조회로 이동.
2. **개별종목 조회** — 종목 입력 → 그 종목을 보유한 ETF 전체 목록. ETF명 클릭 → 전략변화로 이동.
3. **ETF 전략변화** — ETF 1개의 두 시점 비교. **계약수 변화 기준으로 증량·감량·신규·편출 판정.**
4. **ETF별 비교** — ETF 2~5개의 AUM·보유종목 비중 매트릭스.

각 탭에 **⬇ 엑셀** 버튼(.xlsx, 전체 데이터).

## 계산 방식

- **ETF보유액** = 각 ETF 순자산(AUM) × 그 종목의 ETF내 비중(PDF 비중). 보유한 모든 ETF에 걸쳐 합산.
- **ETF보유비중%** (시장전체·조회 상단) = Σ(ETF보유액) ÷ 종목 시가총액 × 100 → **시총 대비**.
- **ETF내 비중%** (조회 표) = 그 **ETF 포트폴리오 안**에서 이 종목이 차지하는 비중(KRX 원자료).
- **계약수** = PDF의 1CU(설정단위)당 보유 수량. 주가·자금유출입과 무관 → **전략 판정의 핵심 지표**.

### 제외 항목
시총 대비 계산은 **국내 상장 개별주식만** 집계합니다.
해외주식·채권·선물·외화현금 등 국내 시총이 없는 항목은 제외(비중 왜곡 방지).
원화현금은 보유액엔 포함(계약수 없음). 다른 ETF 보유분(ETF-in-ETF)은 2025·2026 전 기간 포함.

### 날짜 의미 (중요)
**표시 날짜 = PDF 공표일**이고, 그 구성은 **전 영업일(D-1) 종가 기준 실제 보유**입니다.
→ **편출·매매는 표시일의 전 영업일에 실행**된 것. (PDF가 장 시작 전 전일 기준으로 공표되는 구조)

예: 표시 7/15에서 어떤 종목이 사라졌다면, 실제 매도는 **7/14**에 실행됨.

## 주요 설정 (etf_holdings.py 상단 CONFIG)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `WORKERS` | 10 | 동시 요청 수. KRX가 차단하면 낮추기 |
| `RETRIES` | 4 | PDF 실패 시 재시도 |
| `FAIL_RATIO_LIMIT` | 0.05 | 실패율이 이보다 높으면 저장 안 하고 다음에 재시도 |
| `BATCH_PER_RUN` | 1 | 한 번 실행에 1일치 (매 날짜 새 로그인 → 세션 만료 회피) |
| `MAKE_EXCEL` | False | 엑셀 생성 안 함(웹 데이터만) |

### 실행 옵션
- `--auto` : 최근 영업일 자동 수집(무인). Actions가 사용.
- `--withetf` : ETF가 보유한 다른 ETF도 종목처럼 포함 + `etf_codes.json` 갱신.
- `--year 2026` : 그 해 거래일 전체를 1일씩 이어받기(과거 대량 수집용).

종료코드: `0` 완료 / `2` 이 날짜 완료·다음 진행 / `3` throttle 의심(대기 후 재시도) / `1` 오류

## 운영 메모

- **KRX throttle 주의**: 과도한 요청은 IP 단위 임시 차단으로 이어집니다. `WORKERS`를 무리하게 올리지 말 것.
- **로컬에서 데이터 파일을 수정하지 말 것**: Actions가 같은 파일을 커밋하므로 충돌합니다.
  코드만 수정하고, 작업 전 `git pull`로 원격을 먼저 받으세요.
- **용량**: 하루 약 1.8MB(연 450MB). 저장소가 3GB를 넘어가면 과거 데이터 gzip 압축을 검토.
- 2024년 데이터는 수집하지 않았습니다.
